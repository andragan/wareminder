## ADDED Requirements

### Requirement: Extension SHALL authenticate users through Supabase Auth

The extension SHALL sign users in through Supabase Auth with Google as the identity provider. A successful sign-in SHALL produce a Supabase session containing an access token and refresh token for the signed-in user.

#### Scenario: Interactive sign-in creates a Supabase session

```gherkin
Given the user is not signed in
When the user clicks the sign-in action in the popup
And the extension launches the Supabase Google auth flow with `chrome.identity.launchWebAuthFlow`
Then the extension receives a Supabase session
And stores the session for subsequent authenticated backend calls
```

#### Scenario: Failed sign-in creates no session

```gherkin
Given the user starts the sign-in flow
When the Google or Supabase auth flow fails or is cancelled
Then no authenticated session is stored
And the popup remains in an unauthenticated state
```

### Requirement: Extension SHALL use the Chrome redirect URL for auth completion

The extension SHALL use the redirect URL generated by `chrome.identity.getRedirectURL(...)` as the Supabase OAuth callback target and SHALL parse the final redirect URL returned by `chrome.identity.launchWebAuthFlow(...)` to recover the Supabase session.

#### Scenario: Session is parsed from final auth redirect

```gherkin
Given the extension has started the Supabase Google auth flow
When Supabase redirects back to the Chrome extension redirect URL
Then the extension receives the final redirect URL from `launchWebAuthFlow`
And extracts the Supabase session tokens from that redirect result
```

#### Scenario: Redirect result is never logged as plaintext session data

```gherkin
Given the auth flow completes with a redirect URL containing session data
When the extension processes the result
Then the extension does not write the raw redirect URL or tokens to logs
And stores only the parsed session in extension storage
```

### Requirement: Extension SHALL persist and restore Supabase sessions

The extension SHALL persist the current Supabase session in extension storage and restore it when the service worker or popup starts.

#### Scenario: Valid stored session is restored

```gherkin
Given a previously stored Supabase session exists
When the extension starts
Then the service worker restores the session
And authenticated backend calls can proceed without a new sign-in prompt
```

#### Scenario: Expired access token is refreshed

```gherkin
Given a stored Supabase session has an expired access token and a valid refresh token
When the extension needs authenticated access
Then the service worker refreshes the session
And stores the updated access and refresh tokens
```

#### Scenario: Invalid refresh token clears the stored session

```gherkin
Given a stored Supabase session cannot be refreshed
When the extension attempts session recovery
Then the stored session is cleared
And the user is prompted to sign in again
```

### Requirement: App user records SHALL align to authenticated Supabase users

App-level user data SHALL be keyed from or directly linked to `auth.users.id`. New users SHALL get an app-level profile record associated with the authenticated Supabase user.

#### Scenario: New authenticated user gets an app profile

```gherkin
Given a user signs in successfully through Supabase Auth for the first time
When the backend resolves the authenticated user
Then an app-level user record exists for that `auth.users.id`
And the user is treated as a free-tier user unless a subscription exists
```

#### Scenario: Existing legacy user is linked during migration

```gherkin
Given an existing WAReminder user record created before the Supabase Auth migration
When the migration links that user to a newly created or matched `auth.users` record
Then the user's subscription data remains associated to the same logical account
And future requests use the authenticated Supabase user ID as the canonical key
```

### Requirement: Extension SHALL support explicit sign-out

The extension SHALL provide a sign-out flow that clears the local Supabase session and leaves the popup in an unauthenticated state.

#### Scenario: Sign-out clears session state

```gherkin
Given the user is signed in with a stored Supabase session
When the user signs out
Then the extension clears the stored session
And authenticated subscription/account UI is removed from the popup
```
